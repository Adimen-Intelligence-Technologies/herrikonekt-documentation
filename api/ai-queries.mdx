The AI Queries endpoint is the core of the Adimen AI API. Use it to send natural language requests and receive AI-generated responses, optionally within a persistent session context. Whether you need a one-off answer or a multi-turn conversation, this endpoint handles both stateless queries and session-bound exchanges.

## POST /ai/query

Send a natural language query to the Adimen AI engine.

**Request Body**

<ParamField body="query" type="string" required>
  The natural language request to send to the AI engine. This can be a question, instruction, or any free-form text input.
</ParamField>

<ParamField body="session_id" type="string">
  The ID of an existing session to attach this query to. When provided, the AI engine uses the session's full message history for context continuity. If omitted, a stateless query is made with no prior context.
</ParamField>

<ParamField body="language" type="string">
  A BCP 47 language code to override the response language for this query (e.g. `en`, `fr`, `pt-BR`). Defaults to the language set in your user profile.
</ParamField>

<ParamField body="max_tokens" type="integer">
  The maximum number of tokens to include in the AI's response. Defaults to `1024`. Maximum allowed value is `4096`.
</ParamField>

**Request**

```bash
curl -X POST https://api.adimen.ai/v1/ai/query \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "Summarize the key points of agile project management",
    "session_id": "ses_01abc123xyz",
    "language": "en",
    "max_tokens": 512
  }'
```

**Response (200)**

```json
{
  "id": "qry_01resp789xyz",
  "session_id": "ses_01abc123xyz",
  "query": "Summarize the key points of agile project management",
  "response": "Agile project management is an iterative approach that emphasizes...",
  "tokens_used": 387,
  "created_at": "2024-06-01T10:05:00Z"
}
```

<ResponseField name="id" type="string">
  The unique identifier for this query.
</ResponseField>

<ResponseField name="session_id" type="string">
  The session this query belongs to. Returns `null` for stateless queries made without a `session_id`.
</ResponseField>

<ResponseField name="query" type="string">
  The original natural language request that was submitted.
</ResponseField>

<ResponseField name="response" type="string">
  The AI-generated response to the submitted query.
</ResponseField>

<ResponseField name="tokens_used" type="integer">
  The total number of tokens consumed by this query, including both input and output tokens.
</ResponseField>

<ResponseField name="created_at" type="string">
  The ISO 8601 timestamp indicating when the query was processed.
</ResponseField>

<Note>
  Each query counts `tokens_used` toward your plan's monthly token limit. Monitor your consumption in the Adimen AI dashboard to avoid hitting your plan's cap. Upgrading your plan increases your available token allocation.
</Note>

<Tip>
  Always pass a `session_id` for multi-turn conversations. Without it, the AI engine has no memory of previous exchanges and treats every query as a fresh, isolated request. Create a session first using `POST /sessions`, then reuse its ID across all related queries.
</Tip>

## Streaming Responses

<Info>
  Streaming support via Server-Sent Events (SSE) is currently on the roadmap. This feature will allow you to receive AI response tokens incrementally as they are generated, reducing perceived latency for longer outputs. Check the Adimen AI changelog for availability updates.
</Info>
