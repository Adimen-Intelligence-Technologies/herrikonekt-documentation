The Adimen AI API uses API keys for authentication. Every request must include a valid API key in the `Authorization` header. There are no session tokens or OAuth flows — your API key acts as your credential for all API calls.

## Getting Your API Key

Generate an API key from inside the Adimen AI app before making your first request.

<Steps>
  <Step title="Log in to the Adimen AI app">
    Open the Adimen AI mobile app and sign in to your Business plan account.
  </Step>
  <Step title="Navigate to API Access">
    Go to **Settings → Account → API Access**.
  </Step>
  <Step title="Generate a new key">
    Tap **"Generate New API Key"** to create a fresh key.
  </Step>
  <Step title="Name your key">
    Give the key a descriptive name that identifies where it will be used (e.g., `My App Production` or `Backend Service`).
  </Step>
  <Step title="Copy and store the key">
    Copy the key immediately after it is generated — it is only shown once and cannot be retrieved later.
  </Step>
</Steps>

<Warning>
  Your API key is displayed **only once** at the time of creation. Store it immediately in a secure location such as an environment variable or a secrets manager (e.g., AWS Secrets Manager, HashiCorp Vault, or a `.env` file that is excluded from version control). If you lose the key, you will need to revoke it and generate a new one.
</Warning>

## Using Your API Key

Pass your API key as a Bearer token in the `Authorization` header of every request:

```bash
curl -X GET https://api.adimen.ai/v1/users/me \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json"
```

You can use the same pattern in any language or HTTP client:

<CodeGroup>
  ```python api_client.py
  import requests

  headers = {
      "Authorization": "Bearer YOUR_API_KEY",
      "Content-Type": "application/json"
  }

  response = requests.get("https://api.adimen.ai/v1/users/me", headers=headers)
  print(response.json())
  ```

  ```javascript api_client.js
  const response = await fetch("https://api.adimen.ai/v1/users/me", {
    headers: {
      "Authorization": "Bearer YOUR_API_KEY",
      "Content-Type": "application/json"
    }
  });
  const data = await response.json();
  console.log(data);
  ```
</CodeGroup>

<Tip>
  Store your API key in an environment variable (e.g., `ADIMEN_API_KEY`) and read it at runtime rather than hardcoding it in your source files.
</Tip>

## Programmatic Authentication Endpoints

If you are building a server-side integration, you can obtain API tokens programmatically using the `register` and `login` endpoints instead of generating a key manually in the app. Both endpoints are unauthenticated — no API key is required to call them.

### POST /auth/register

Create a new Adimen AI account and receive an API token in return. Use this endpoint to provision accounts for your users programmatically.

**Request Body**

<ParamField body="email" type="string" required>
  The email address for the new account. Must be unique across all Adimen AI accounts.
</ParamField>

<ParamField body="password" type="string" required>
  The password for the new account. Must be at least 8 characters and contain a mix of letters and numbers.
</ParamField>

<ParamField body="display_name" type="string">
  An optional display name for the new user. If omitted, the account is created without a display name.
</ParamField>

**Request**

```bash
curl -X POST https://api.adimen.ai/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "email": "user@example.com",
    "password": "SecurePass123",
    "display_name": "Jane Smith"
  }'
```

**Response (201)**

```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": {
    "id": "usr_01hxyz123abc",
    "email": "user@example.com",
    "display_name": "Jane Smith",
    "plan": "free",
    "created_at": "2024-06-01T10:00:00Z"
  }
}
```

<ResponseField name="token" type="string">
  A Bearer token you can use immediately to authenticate API requests. Treat this value like an API key — store it securely and include it in the `Authorization` header of subsequent requests.
</ResponseField>

<ResponseField name="user" type="object">
  The newly created user object, including `id`, `email`, `display_name`, `plan`, and `created_at`.
</ResponseField>

**Error responses**

| Status | Code | Description |
|---|---|---|
| `400` | `invalid_request` | Required fields are missing or the password does not meet requirements. |
| `409` | `conflict` | An account with the provided email address already exists. |

### POST /auth/login

Authenticate an existing account and receive an API token. Use this endpoint to obtain a token for a user who already has an Adimen AI account.

**Request Body**

<ParamField body="email" type="string" required>
  The email address associated with the account.
</ParamField>

<ParamField body="password" type="string" required>
  The account password.
</ParamField>

**Request**

```bash
curl -X POST https://api.adimen.ai/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "email": "user@example.com",
    "password": "SecurePass123"
  }'
```

**Response (200)**

```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": {
    "id": "usr_01hxyz123abc",
    "email": "user@example.com",
    "display_name": "Jane Smith",
    "plan": "pro",
    "created_at": "2024-01-15T10:30:00Z"
  }
}
```

<ResponseField name="token" type="string">
  A Bearer token to use in the `Authorization: Bearer <token>` header for all subsequent API requests.
</ResponseField>

<ResponseField name="user" type="object">
  The authenticated user object, including `id`, `email`, `display_name`, `plan`, and `created_at`.
</ResponseField>

**Error responses**

| Status | Code | Description |
|---|---|---|
| `400` | `invalid_request` | Required fields are missing or malformed. |
| `401` | `unauthorized` | The email or password is incorrect. |
| `423` | `account_locked` | The account is temporarily locked after too many failed login attempts. Wait 15 minutes before retrying. |

<Note>
  Tokens obtained via `/auth/login` and `/auth/register` follow the same Bearer token format as API keys generated in the app. Pass the returned `token` value in the `Authorization: Bearer <token>` header on every subsequent request.
</Note>

## Managing API Keys

View and manage all of your active API keys at **Settings → Account → API Access**. Each key in the list displays:

- **Name** — the label you assigned when generating the key
- **Created** — the date the key was generated
- **Last used** — the most recent date the key was used to make a successful request

To revoke a key, tap the **trash icon** next to it. Revocation is immediate — any requests using that key will start returning `401 Unauthorized` right away. Revoked keys cannot be restored; generate a new key if needed.

## Key Scopes

By default, an API key has access to all API endpoints permitted by your plan. If you need tighter control, **scoped keys** are available on Business plans:

| Scope | Access |
|---|---|
| **Full Access** (default) | All endpoints your plan permits. |
| **Read-Only** | `GET` requests only; no writes or AI queries. |
| **AI-Only** | AI query endpoints only; no user or account data. |

To create a scoped key, go to **Settings → Account → API Access → Advanced** and select the desired scope when generating the key.

## Authentication Errors

If your request fails authentication, the API returns one of the following errors:

| Status | Meaning |
|---|---|
| `401 Unauthorized` | The `Authorization` header is missing, malformed, or contains an unrecognized or revoked key. |
| `403 Forbidden` | The key is valid, but it does not have permission to access the requested resource (e.g., a scoped key attempting a restricted endpoint). |

Check that your key is correctly formatted as `Bearer YOUR_API_KEY` and that it has not been revoked before retrying.

<Note>
  Never expose your API key in client-side code, browser-side JavaScript, or version control. If a key is ever compromised, revoke it immediately from **Settings → Account → API Access** and issue a new one.
</Note>
