## Qué hace

Permite responder dos preguntas por municipio:

- **"¿Cuándo pasa el próximo autobús / tren desde mi pueblo?"** — paradas cercanas con sus **próximos pasos** (hora programada, hora estimada, retraso, indicador de tiempo real).
- **"¿Qué líneas llegan aquí y a dónde van?"** — las líneas que conectan el municipio y con qué otros municipios.

## Fuente de datos

**Moveuskadi — Open Data Euskadi**:

- Datos: GTFS estático (paradas, líneas, horarios) + GTFS-RT (tiempo real: posición de vehículos, retrasos, alertas)
- Cobertura: Metro, tranvía, buses urbanos e interurbanos, tren regional, cercanías, funicular (toda Euskadi)
- Licencia: CC-BY 4.0
- Actualización: GTFS estático diario; GTFS-RT cada 30 segundos

## Stack técnico

**Backend (`herrikonekt-server`):**

- Librerías: `unzip` (GTFS estático), `gtfs-realtime-bindings` (GTFS-RT protobuf)
- Importación: Script `lib/services/transporte/gtfs/` con parseo por operador
- Colecciones precomputadas para O(1) lookup de salidas por parada
- Caché de tiempo real con TTL corto (≤ 60s, bajo demanda)

**App (`Herrikonekt`):**

- Pantalla principal: `app/transportes.tsx`
- Hooks: `use-transportes-screen.ts`, `use-transporte-paradas.ts`, `use-transporte-resultados-screen.ts`, `use-transporte-resultado-detalle-screen.ts`
- Componentes: Modales de selección, LugarInput (autocomplete de paradas)
- Cliente de red: `lib/api/transporte.ts` vía `lib/subscriber` (caché con TTL corto para tiempo real)
- Sin cambios nativos → entregable como OTA

## Consideraciones

### Volumen de datos

El GTFS estático es **voluminoso** (~50-200 MB por operador). Se resuelve:

- Descargando **por operador** (lista blanca `TRANSPORTE_FEEDS`)
- Precomputando una tabla de **salidas por parada** (O(1) lookup)
- Usando **caché en Mongo** para evitar reprocesar

### Licencia

Atribución obligatoria: _"Datos: Moveuskadi — Open Data Euskadi (CC-BY 4.0)"_ + cada operador.
