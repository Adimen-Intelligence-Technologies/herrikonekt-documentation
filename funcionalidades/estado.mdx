## Infraestructura y operaciones

### Bases de datos

- **MongoDB Atlas** — 28 colecciones, cluster `adimencrm`, producción con copias de seguridad locales en `backups/`.
- **~50 índices** declarados: únicos parciales, TTL (30 días para historial), 2dsphere para proximidad, multikey para arrays.
- **Auditoría**: cada cambio queda registrado en `historialCambios` (append-only, TTL 30 días).

### Documentación de API

- **OpenAPI 3.1** — Servido en `/api/openapi.json` y renderizado en `/api/docs` (Scalar).
- **Schemas Zod v4** — Única fuente de verdad de la forma de documentos.
- **Validación:** toda entrada y salida validada con Zod antes de persistir.

### Autenticación y autorización

- **better-auth 1.6** — Email + password, Apple, Google.
- **Roles** — `admin` (plataforma), membresía de comercio (`owner`, `admin`).
- **Sesión** — Cookie HTTP-only, optional (app funciona sin login).
- **MCP API keys** — Autenticación programática para administradores.

### Pipeline de calidad

- **TypeScript estricto** (`tsc --noEmit`).
- **ESLint flat config** (`--max-warnings 0` en CI).
- **GitHub Actions** — Lint + typecheck en cada push a `main` y PR.
- **OpenSpec** — Gestión de cambios con sincronización a GitHub Issues (móvil).

### Despliegue y actualización

- **App móvil** — EAS Build (development, preview, production) + EAS Update (OTA con `appVersion`).
- **Backend y panel** — Vercel (build automático en cada push a `main`). Crons nativos para sincronización de feeds.
- **Dashboard** — Vercel (futuro).

## Resumen de trabajo pendiente

1. **Verificación en dispositivo** — Pruebas E2E manuales de reclamación multipart, rendimiento de listados.
2. **Build EAS nativo** — Necesario para `expo-calendar` y Google Sign-In en iOS.
3. **Integración de Tréboles** — Servidor listo; falta conectar en la app (opt-in + límite diario).
4. **Monetización** — Decisión de modelo de negocio y flujos de pago in-app.
5. **Panel de comercios** — Scaffolding hecho; falta implementar edición, ofertas, anuncios de pago.
6. **Funcionalidades futuras** — Evaluación de viabilidad y priorización (gasolineras, playas, transporte, etc.).
